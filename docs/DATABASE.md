# Database Design

> Status: **Draft v1** · Last updated: 2026-10-19
> PostgreSQL 18 · Prisma · see [PLAN.md](PLAN.md) and [ADR-0006](adr/0006-postgresql-and-prisma.md)

This is the logical design. The Prisma schema in Phase 1 is written from it and may adjust names or types; changes are recorded here.

---

## 1. Conventions

| Convention | Rule |
|---|---|
| Primary keys | `id UUID` generated as **UUIDv7** (time-ordered, good index locality) |
| Names | Tables `snake_case` singular in SQL (`product_variant`), models `PascalCase` in Prisma |
| Timestamps | `created_at`, `updated_at` (`timestamptz`, UTC) on every mutable table |
| Soft delete | `deleted_at timestamptz NULL` on product, customer and order-related tables. Queries exclude deleted rows by default. |
| Money | `integer` **piasters** (EGP × 100). Column names end in `_amount` or are clearly money (`price`, `total`). |
| Translations | `jsonb` shaped `{ "ar": string, "en"?: string }`, called **`LocalizedText`** below and validated by a Zod schema |
| Enums | Postgres enums via Prisma for fixed state sets (statuses); lookup tables for anything staff can edit |
| Ownership | Every table belongs to **one module**. Only that module's repository reads or writes it (exception: `reports`, read-only). |
| Concurrency | `version integer` on `order` for optimistic locking |
| Phone numbers | Stored normalized in **E.164** (`+201001234567`) |

Legend in the tables below: **PK** primary key · **FK** foreign key · **U** unique · **IX** index · `?` nullable.

## 2. Entity overview

```
identity:   user ─< session, account, verification       (Better Auth)
            user ─< user_role >─ role ─< role_permission >─ permission
customers:  customer ─< address >─ area
            customer ─o user
delivery:   governorate ─< area >─ delivery_zone
            driver ─o user ; shipment >─ driver ; cash_settlement ─< shipment
catalog:    category (tree) ─< category_attribute
            category ─< product >─ brand ; product ─< product_variant ; product ─< product_media >─ media
inventory:  stock_location ─< stock_level >─ product_variant ; stock_movement (ledger)
cart:       cart ─< cart_item >─ product_variant
orders:     order ─< order_item ; order ─< order_status_history ; order ─< order_note
            order >─ customer ; order >─ stock_location (fulfilment)
payments:   payment >─ order ; payment ─o media (receipt)
delivery:   shipment >─ order
promotions: coupon ─< coupon_target ; coupon_redemption
reviews:    review >─ product, customer ; wishlist_item
content:    banner, page, faq
settings:   setting
audit:      audit_log
jobs:       pgboss.*  (managed by pg-boss in its own schema)
```

## 17. Search implementation notes

- SQL function `normalize_ar(text)`: removes tashkeel and tatweel, maps أ/إ/آ → ا, ة → ه, ى → ي, lowercases Latin text.
- The `product.search_text` column is rebuilt by the catalog service on save from: normalized `name.ar`, `name.en`, brand names (ar/en), variant model numbers and SKUs, and key spec values.
- Queries combine:
  1. `search_vector @@ websearch_to_tsquery('simple', normalize_ar(q))`, ranked by `ts_rank`
  2. `search_text % normalize_ar(q)` (pg_trgm) for typos and partial model numbers (`rt38`)
- Extensions: `pg_trgm`, `unaccent`, `citext`.
- Filters: `specs @> '{"no_frost": true}'` and range filters on numeric spec keys. Fine at hundreds of products; expression indexes can be added per hot attribute if needed.

| Event | Published by | Consumed by |
|---|---|---|

| `PaymentReceiptUploaded` | payments | notifications (staff), orders (payment_status) |
| `PaymentVerified` / `PaymentRejected` | payments | orders (payment_status), notifications, audit |
| `ShipmentDelivered` | delivery | orders (→ delivered), payments (COD → paid) |

Events are dispatched **after the transaction commits**. Listeners that must not be lost (emails) enqueue a pg-boss job instead of doing the work inline.
